# CRS regression and operating limits

The isolated `tools/crscheck` module runs all 5,193 cases in the upstream CRS 4.30.0 test corpus using go-ftw 2.6.2 against a real local HTTP listener. Run `go run .` in that directory. Reports record original expectations, effective expectations, rule IDs, response status, adaptations and failures. No tests are skipped, ignored or force-passed. `go run . -raw -out ../../artifacts/crs-regression-raw.json` runs the unchanged corpus, including expectations written for Apache and its multipart parser. It deliberately reports incompatibilities rather than concealing them.

The default run uses the individually documented expectations in `compatibility.go`. These cover Go protocol rejection, CONNECT rejection, empty/missing Host representation, Coraza multipart errors, detection-only responses, duplicate Content-Type representation, and one raw-header fixture that go-ftw cannot construct from structured input. Every adapted case still executes and asserts concrete behavior. This is connector compatibility testing, not a claim of a measured attack-detection percentage.

The test-only engine profile uses detection-only PL4 and the upstream fixture limits, including argument-count and JSON-depth overrides. It does not replace tests of the production enforcing policy. Production defaults limit argument parsing to 256 and JSON depth to 64. Focused HTTP/2, WebSocket, streaming and crash/fault checks now exist; see [protocol and recovery evidence](PROTOCOL-AND-RECOVERY.md). Exhaustive protocol and sustained-load qualification remain open.

Coraza is pinned to upstream commit `08aa5114730064b86e62d15bbc1fa7e6fdf94f57`, Go module version `v3.8.2-0.20261029104012-08aa51147300`. This is a development revision, not a released stable 3.8.2. The Windows path normalization fix eliminated 75 failures observed with 3.8.1. Upgrade to a stable release containing the fix only after rerunning both reports. Upstream CRS files are unchanged.

## Process capacity

Flags default to `-max-concurrent 64`, `-max-connections 256`, `-buffer-mib 256`, `-body-timeout 15s`, and `-request-timeout 60s`. A nonblocking admission gate reserves conservative request/response copy budgets before creating a transaction. Exhaustion returns 503 with Retry-After: 1 and an overload event. Reservations are released on every exit. Upstream connections are bounded; management handlers have a separate 16-request gate. Request/response size limits still apply independently.

The buffer budget is not a total Go heap or CPU cap: compiled rules, engine parsing, transport buffers and runtime memory remain additional costs. Use OS/container memory and CPU limits, then size concurrency using measurements. The accepted-connection limit leaves excess connections in the OS backlog. Total request context deadlines bound upstream operations; body read deadlines bound slow uploads. Synchronous engine/regex evaluation is not preempted by a context deadline, and retains its reservation until it returns. Application admission shares do not implement CPU-time isolation; see the [CPU-heavy measurements and limits](M4-CPU-QUALIFICATION.md). Public header timeout is five seconds, maximum header size is 64 KiB. CONNECT, literal URI fragments, request trailers and non-WebSocket upgrades are rejected in every mode.

## Durable security events

SQLite defaults to `<policy path>.events.db`, with `-event-db` to override; flags default to `-event-db-mib 64`, `-event-rows 10000`, `-event-days 7`. Security events are retained; clean request totals and charts remain process-local. Restart reloads the recent event view. Search `/api/v1/events/search?limit=100&before=<sequence>&action=blocked&q=<literal text>` using the existing administrator authentication. Search is limited to 128 bytes; page limit is 499; cursors are descending immutable sequence numbers. The console supports search, older pages and export of loaded results.

Gateway security events now use acknowledged group commits with bounded backpressure: a 256-entry queue, batches up to 128 and a 10 ms grouping window, with a five-second default commit wait. Overload rejections use explicit counted one-second summaries instead of one disk row per request. Each serialized event remains at most 16 KiB. See [event delivery](EVENT-DELIVERY.md) for crash windows, retries and the transactional export outbox. Events cap rule matches, tags, targets and metadata; truncated events are marked. Request bodies, query strings, cookies, authorization values and expanded matched values are not stored. Rule messages retain unexpanded static templates; paths, field names and administrator-authored rule text can still contain sensitive information. Apply access controls and a retention policy to this database.

SQLite uses synchronous FULL commits, DELETE journaling and a hard main-file page cap. Logical local-history accounting uses half the main budget when export is unused. With export enabled, history and the independent unacknowledged outbox each use a quarter, leaving space for indexes and pages. History uses oldest-first eviction by row and space quota; pending exports are never evicted. Expired events disappear from database queries immediately and are physically pruned on writes or the minute maintenance tick. Main-file allocation is reused rather than automatically shrinking. A rollback journal can temporarily require approximately another database's size; provision disk accordingly. These are local files, not encrypted or tamper-evident audit records. Back up a stopped database; do not copy a live database as an asserted consistent backup.

Startup refuses corrupt, unsupported or over-budget databases. Runtime write trouble does not disable WAF decisions. Status and the System page expose pending writes, dropped records, failed writes and errors. Loss counters are process-local and keep health degraded for that process even after later writes recover. Queued events can be lost on an abrupt crash; graceful shutdown drains the queue. A healthy completed commit survives ordinary restart; focused forced-process-crash recovery is tested, while power-loss recovery and broader fault timing remain release gates. Export now provides durable at-least-once delivery for committed outbox records to an acknowledging/deduplicating collector, within finite spool limits. It does not guarantee delivery through unlimited outages or device/power loss.
