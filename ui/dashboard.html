REVERSE PROXY

Upstream pool

Round-robin selection with passive failure detection. Observed 5xx/connection failures open a circuit. Recovery allows one trial after cooldown. Application-level request replay is disabled.

Backend observations load after activation.

The application listener is configured at startup. Management routes are served only on the separate loopback console listener.

Traffic handling

Request bodies are bounded and inspected before forwarding. Client identity follows the configured proxy trust profile.

Rate controls and admission

Schema-2 applications receive equal fixed shares of process concurrency and buffer capacity. Zero disables a rate or uses the application share for concurrency. Limits apply in every inspection mode. Client identity follows the configured proxy trust profile.

Rate and burst must both be positive or both zero. Client tables hold at most 1,024 identities per application. Rate rejection returns 429. Admission rejection returns 503. Both include Retry-After.

Inspection policy

Changes take effect for new requests after successful compilation and save.

OWASP CRS

Response body inspection

Inspect HTML, plain text, JSON, and XML before delivery.

Enabled inspection buffers eligible responses up to your limit. Oversized or unexpectedly compressed eligible responses fail with HTTP 502. Leave off for streaming text responses. CRS can block leakage; automatic data redaction is not implemented.

Scoped exceptions

Permit a specific field on one exact path and HTTP method.

Exceptions affect selected request-body-phase rules in this application. If a field name occurs in both the query and body, the exception is withheld and the request stays fully inspected. Save & apply activates changes.

CRS rule exceptions

Exclude individual rule IDs after investigating a false positive.

Release scope

Exact hostname routing supports up to eight applications, each with its own upstream pool and security policy. Certificate files support validated live renewal, and administration activity has a separate durable journal. Linux service packaging is available for an initial deployment. Administration, resource limits, counters and revision rollback cover the whole deployment. Local accounts support administrator, operator and viewer roles, application assignments, scoped automation tokens, passkeys and optional organization SSO.

Listener and certificate paths are startup settings. Your certificate provider renews the PEM files. The console shows reload failures and expiry warnings. Gateway errors appear in security events.

Administrator enrollment required

Deployment policy requires administrator MFA. Enroll a local factor below, then sign in with TOTP or verify a passkey to open the security console. Bootstrap recovery remains available.

Administrator authentication policy

Require verified MFA for every named administrator. Password-only sessions receive enrollment access. At least one enabled administrator needs an enrolled local factor.

A passkey or assured SSO session verified within two minutes can authorize this change without entering these credentials again.

Local accounts

Administrators manage up to 32 local accounts. Operators change application policies. Viewers have read access. Saving an existing account revokes its sessions. The server bootstrap token retains full recovery authority and requires separate protection.
